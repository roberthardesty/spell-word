# Changelog

Notable changes per branch/commit. Newest first. Format loosely follows Keep a Changelog; entries reference Vikunja task IDs (project: Spell-Word) where applicable.

## Unreleased

### Changed

- **TFLM tensor arena → internal SRAM** (Vikunja #39 — AFK portion, PRD §"Sequencing" step (a); ADR-0001, ADR-0005). `letter_recognizer.cpp::setup_interpreter` now allocates the tensor arena with `MALLOC_CAP_INTERNAL` instead of `MALLOC_CAP_SPIRAM`. PSRAM placement is 3-5× slower for TFLM operators on ESP32-S3, so the early-commit silence floor (ADR-0001, 500 ms) and W-recovery re-inference (ADR-0005, ~40 ms) both required SRAM placement to hold their latency claims. `SPELL_TENSOR_ARENA_SIZE` shrunk from 512 KB → 256 KB as a pessimistic ceiling for the new 51 KB model (expected `arena_used_bytes ≈ 100-150 KB`); the existing init-time log line `"interpreter ready — arena used N / M B"` exposes the actual figure so the ceiling can be tightened to ≤ 1.2 × measured after on-board boot. Stale arena-PSRAM comment block at the head of `letter_recognizer.cpp` updated to reflect the SRAM rationale; the Core 1 IDLE-WDT-disable comment kept (with a note explaining it now guards against future-larger-model regressions rather than the historical ~250 ms PSRAM-arena Invoke). `idf.py build` clean (`spell_word.bin` 0x63230 bytes, 81% app partition free — same as before, since this is alloc-cap + size-constant only); 12/12 decoder + 10/10 w_detector + 12/12 segmenter host tests still pass. Hardware-bound acceptance criteria (load 51 KB model into the `model` partition; confirm invoke time in 30-40 ms; verify SRAM headroom in production firmware) remain on Vikunja #39 — code change is shipped, bench verification is the only blocker for closing the task and unblocking #30 (W-recovery integration).

### Added

- **`decoder_replay` host CLI + fixture format** (Vikunja #24, PRD §"Posterior assembly", §"Aggressive early-commit predicate"). New `tools/decoder_replay/main.c` builds a `decoder_replay` binary alongside the existing `test_decoder_core` rig, both linking the same `components/decoder/decoder_core.{c,h}` that runs on-device. Fixture rows are tagged: `L` carries 5×(letter, prob) plus a `retract_count` and feeds `dec_on_letter` then evaluates `dec_try_early_commit(silence_floor=false)`; `W` simulates `EARLY_COMMIT_WINDOW` and evaluates with `silence_floor=true` (auto-resets state on commit so the next word can stream in cleanly); `E` calls `dec_resolve_full_eow` and resets; `R` resets without resolving. End-of-file with non-empty in-flight state triggers an implicit EOW so simple per-utterance fixtures need no trailing tag. Letters accept either single ASCII A–Z (case-insensitive) or numeric 0–25; comments + blanks skipped; whitespace-tolerant comma-separated cells. Dictionary loaded from a `--dict` text file (one `<word_id> <LETTERS>` per line, length capped at `SPELL_MAX_LETTERS_PER_WORD`); the confusion matrix loads from `--matrix` (26×26 floats, space- or comma-separated) or defaults to the same neutral diag=0.6 / off=0.4/25 shape used by `test_decoder_core.c`'s baseline. Every tunable in `dec_config_t` is exposed as a CLI flag — `--alpha`, `--decision-margin`, `--ins-penalty`, `--del-penalty`, `--early-margin-runnerup`, `--early-margin-longer` — defaulting to the `spell_config.h` values reported by `dec_config_default()`. Per-event lines log all five top-K candidates, the retract count, and the early-commit predicate's per-clause flags + computed margins (so US-13 diagnostic logging can be exercised end-to-end against real fixtures); per-EOW lines log resolved word + score + margin, or ABSTAIN with margin and overflow flag. Trailing summary tallies events by type, resolutions, abstains, early-commit hits, and parse errors. Bundled `fixtures/sample.csv` + `fixtures/sample_dict.txt` exercise both the clean-CAT early-commit path and the W-recovery `retract_count = 2` cycle through to a WAT resolution. `make` builds both binaries; `make test` runs the 12-case unit rig and still passes. `idf.py build` clean (`spell_word.bin` 0x63230 bytes, 81% free — host-only change).
- **Letter recognizer PCM ring** (Vikunja #27, PRD §"Sequencing" step (d); ADR-0005). The recognizer now retains the last `SPELL_W_DETECT_PCM_RING_DEPTH = 4` inference-eligible utterance windows in a single contiguous PSRAM block sized at `SPELL_W_DETECT_PCM_RING_DEPTH × SPELL_INFERENCE_WINDOW_BYTES = 102 400 B (~100 KB)`. The block is allocated once at `letter_recognizer_init()` time via `heap_caps_malloc(MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)`; allocation failure logs a precise size + depth message and returns `ESP_ERR_NO_MEM`, which `app_main`'s `ESP_ERROR_CHECK(letter_recognizer_init())` turns into a loud boot abort. `pcm_ring_insert(pcm, n_samples)` is called from the recognizer task only on the inference-success path (after `esp_event_post(LETTER_RECOGNIZED)`) — gate-skipped, no-model, invoke-failed, and invalid-drop paths still free the inbound buffer immediately as before, so the ring tracks utterances that produced a top-K event. Insertion copies up to `SPELL_INFERENCE_WINDOW_SAMPLES` int16 samples into the head slot, right-pads any short tail with zero (defensive — the segmenter already zero-pads), records the slot's `n_samples`, advances `s_pcm_ring_head` modulo depth, and bumps `s_pcm_ring_count` (saturating at `DEPTH`). The ring is purely internal to the recognizer translation unit — `s_pcm_ring_storage`, `s_pcm_ring_n_samples`, `s_pcm_ring_head`, `s_pcm_ring_count` are file-scope `static`s with no header declarations, and `pcm_ring_insert` is `static` — because the W-recovery cycle (#30, ADR-0005) is the only consumer and it lives inside the same recognizer task, so no public access function is justified. Existing inference-pipeline behavior is unchanged when the ring is not consulted; the only added cost on the success path is one ~25.6 KB PSRAM-to-PSRAM `memcpy` per utterance. Init-time log line `"PCM ring allocated: 4 slots × 25600 B = 102400 B PSRAM"` makes the budget visible against the 100 KB PRD target. `idf.py build` clean (`spell_word.bin` 0x63230 bytes, 81% app partition free); 12/12 decoder host tests still pass; 10/10 w_detector host tests still pass. Removes the last AFK gate on Vikunja #30 (W-recovery integration) — only the TFLM arena precursor (#39, hardware-dependent) remains.
- **Decoder IDF wrapper + matrix/dict partition loaders** (Vikunja #22, PRD §"Decoder", sequencing step (h); ADR-0001, ADR-0006). New `components/decoder/decoder.{c,h}` wraps the pure-C `decoder_core` with `esp_event` glue and partition loading. `decoder_init()` finds the confusion partition (subtype 0x81, label `confusion` per `partitions.csv`) and the dictionary partition (subtype 0x82, label `dictionary`), reads them into PSRAM via `esp_partition_read`, and validates strictly: every confusion-matrix row sum must lie in 1.0 ± 1e-3 with non-negative finite entries; the dictionary header must carry magic `SPDC` + version 1, every record must have length in [1, `SPELL_MAX_LETTERS_PER_WORD`] with each letter index in [0, 25], and the byte-stream walk must stay inside the partition. Any failure — missing partition, erased flash (0xFF magic at offset 0), out-of-tolerance row sum, malformed record — returns a non-OK `esp_err_t` with a precise `ESP_LOGE` line and leaves the wrapper inert (no handlers registered). This diverges intentionally from `letter_recognizer.cpp`'s soft-fail-on-empty handling: the matrix and dictionary are load-bearing for any decoder output, while the model can defer to OTA. After successful init, the wrapper subscribes to `SPELL_RECOGNIZER_EVENT::LETTER_RECOGNIZED` (calls `dec_on_letter` then evaluates `dec_try_early_commit(silence_floor=false)`), `SPELL_SEGMENTER_EVENT::EARLY_COMMIT_WINDOW` (re-evaluates with `silence_floor=true`), and `SPELL_SEGMENTER_EVENT::END_OF_WORD` (calls `dec_resolve_full_eow`). On any RESOLVED outcome it publishes `SPELL_DECODER_EVENT::WORD_RESOLVED` with the full `spell_word_resolved_event_t` payload (`word_id`, `commit_reason` ∈ {`EARLY`, `FULL_EOW`}, `score_margin`) and resets the in-flight buffer; on full-EOW ABSTAIN it publishes `SPELL_DECODER_EVENT::WORD_ABSTAIN` (empty payload). Handlers run on the default event-loop task — no separate task — since per-event work is bounded and ms-scale. `app_main.c` calls `decoder_init()` after `audio_dump_init` and soft-fails (logs warning, continues boot) when the partitions are erased, so dev boards still spell "into the void" via the recognizer's bring-up logging until matrix + dict are flashed. `partitions.csv` already carried the `confusion`/`dictionary` entries with the right subtypes from prior work; new label macros `SPELL_MATRIX_PARTITION_LABEL` and `SPELL_DICT_PARTITION_LABEL` in `spell_config.h` keep the strings in one place. Dictionary binary format is documented at the head of `decoder.c` (16-byte header `magic[4]='SPDC' | uint32 version=1 | uint32 n_words | uint32 reserved=0`; packed records `uint32 word_id | uint8 length | uint8 letters[length]`). `idf.py build` clean (`spell_word.bin` 0x630b0 bytes, 81% app partition free); 12/12 decoder host tests still pass; 10/10 w_detector tests still pass. Unblocks Vikunja #25 (UI state machine), #30 (W-recovery integration), and #31 (per-spelling summary log line).
- **`w_detector_replay` host CLI + CSV fixture format** (Vikunja #29). New `tools/w_detector_replay/main.c` builds a `w_detector_replay` binary alongside the existing `test_w_detector_core` rig, both linking the same `components/letter_recognizer/w_detector_core.{c,h}` that runs on-device. CSV input is `event_n, top1_letter, top1_prob [, ... ]` per row — extra columns are tolerated and ignored (so future top-2/top-3 fixtures stay forward-compatible), `#` comments and the optional `event_n` header row are skipped, `top1_letter` accepts either a single ASCII letter A–Z (case-insensitive) or a numeric alphabet index 0–25, `top1_prob` is in [0, 1]. Per-event output prints the trigger boolean plus the five per-condition diagnostic flags (`hist=2/2|<2`, `is_u`, `hi`, `p1_lo`, `p2_lo`) so US-16 logging can be exercised end-to-end. Both `SPELL_W_DETECT_*` thresholds are overridable by CLI flag (`--u-threshold`, `--low-conf-threshold`); reads from a path or from `-` (stdin); `--quiet` suppresses per-event lines for sweep scripts; bad rows are reported with line number, drained, and produce a non-zero exit so CI can gate on parse errors. Bundled `fixtures/sample.csv` exercises the warm-up window, a confident non-W passthrough, the canonical lo-lo-U trigger, and a consecutive-trigger run. `idf.py build` clean (`spell_word.bin` unchanged at 0x611b0 bytes — main.c is host-only); 10/10 unit tests still pass.
- **`w_detector_core` — W-recovery trigger predicate** (Vikunja #28, PRD §"W-detection trigger", sequencing step (e); ADR-0005). New pure-C99 sub-module of the recognizer at `components/letter_recognizer/w_detector_core.{c,h}`. `wdet_on_event(top1_index, top1_prob)` evaluates the four-condition predicate (current top-1 == 'U', current_prob ≥ `SPELL_W_DETECT_U_THRESHOLD`, both prev[1] and prev[2] top1_prob < `SPELL_W_DETECT_LOW_CONF_THRESHOLD`) against a sliding window of the two most recent prior events, then shifts the new event into the window. Returns `wdet_eval_t` carrying the trigger boolean plus per-condition diagnostic flags + the current event values for US-16 logging. `wdet_config_t` makes both thresholds overridable so host tests can pin boundaries without touching `spell_config.h`. Operates on top-K event metadata only — no PCM, no inference, no IDF. The recognizer (Vikunja #30) holds the U emission, concatenates the last 3 PCM buffers from the ring (#27), and re-runs inference on trigger; this sub-module just fires the predicate. Ten host tests in `tools/w_detector_replay/test_w_detector_core.c` cover the eight acceptance scenarios (3 hi-conf non-W → no trigger; 2 lo + hi U → trigger; 2 hi + hi U → no; 2 lo + hi non-U → no; 2 lo + lo U → no; threshold boundary cases — `>=` for U, strict `<` for prev; not-enough-history; consecutive W-W triggers) plus reset semantics and current-event diagnostic carry-through. All 10 pass; decoder tests still pass (12/12); `idf.py build` clean (`spell_word.bin` 0x611b0 bytes, 81% free). Unblocks Vikunja #29 (w_detector_replay CLI) and is one of the four prerequisites for Vikunja #30 (W-recovery integration).
- **`decoder_core` — aggressive early-commit predicate** (Vikunja #21, PRD §"Aggressive early-commit predicate", sequencing step (g, second half); ADR-0001). New `dec_try_early_commit(state, silence_floor_satisfied)` evaluates the three-clause predicate as a pure read-only function over the same in-flight state used by `dec_resolve_full_eow`: clause 1 (`margin_runnerup > SPELL_EARLY_MARGIN_RUNNERUP`, default 3.0) compares against same-length runner-up; clause 2 (`margin_longer > SPELL_EARLY_MARGIN_LONGER`, default 2.0) compares against the best length-(N+1) or length-(N+2) competitor scored under the deletion-penalty path (extended to 2-skip combinations); clause 3 is the post-letter silence floor (`SPELL_EARLY_MIN_SILENCE_MS`, default 500 ms), supplied by the caller as a boolean — false on `LETTER_RECOGNIZED` events, true on `EARLY_COMMIT_WINDOW` events. The returned `dec_early_commit_eval_t` carries per-clause `_ok` flags plus computed margins for US-13 diagnostic logging. `dec_config_t` extended with `early_margin_runnerup` and `early_margin_longer` so tests can sweep thresholds. Five new host tests in `tools/decoder_replay/test_decoder_core.c` cover: clean commit when all three clauses pass; each clause failing in isolation (silence floor, runnerup margin, longer-competitor margin); and the prefix-truncation safeguard (BAN inside BANK) — silence floor is the load-bearing clause when `|del_penalty|` exceeds the longer-margin threshold, exactly the scenario ADR-0001 calls out. All 12 decoder tests pass; `idf.py build` clean. Unblocks Vikunja #22 (decoder IDF wrapper) and #24 (decoder_replay CLI).
- **`decoder_core` — full-EOW resolution + unified retract-aware letter handler** (Vikunja #20, PRD §"Posterior assembly", §"Decoder letter-event handler (unified)", sequencing step (g); ADR-0006). New pure-C99 host-portable `components/decoder/` with `decoder_core.{c,h}` and a dedicated CMakeLists. The unified `dec_on_letter(top_k, retract_count)` handler is one code path: pop `retract_count` entries from the in-flight buffer, append `top_k` (overflow at `SPELL_MAX_LETTERS_PER_WORD` sets a flag rather than crashing). `dec_resolve_full_eow()` assembles per-letter posteriors as `(1 − α) · net_prob + α · M[top1, ·]` with the outside-top-K mass split uniformly across the 21 non-top-K letters, then scores every dictionary word under three alignment strategies — exact length, one inserted utterance (cough — `SPELL_EDIT_INS_PENALTY`), one missed letter (swallowed pause — `SPELL_EDIT_DEL_PENALTY`) — and abstains when the best/runner-up margin falls below `SPELL_DECISION_MARGIN`. Seven host tests in `tools/decoder_replay/test_decoder_core.c` cover the acceptance set: clean resolution, confusion-pair recovery, 1-edit insertion, 1-edit deletion, abstain on flat distribution, overflow → abstain, and `retract_count = 2` correctly dropping two prior entries (with a defensive clamp sub-case). Early-commit predicate, IDF wrapper, and partition loaders are intentionally out of scope; they land in Vikunja #21 and #22 against this same in-flight state.
- **Segmenter early-commit-window event** (Vikunja #19, PRD §"Modules"/§"Sequencing" step (c)). `seg_core` now fires `SEG_EVT_EARLY_COMMIT_WINDOW` exactly once per inter-letter silence cycle when the post-letter frame count crosses a new `early_commit_frames` config (defaulted to `SPELL_EARLY_MIN_SILENCE_MS = 500 ms` in the IDF wrapper). Latch resets on next letter onset. `seg_init` validates `0 < early_commit_frames < eow_frames` so the window event is always observed before EOW in the same silence stretch. The IDF wrapper republishes `SPELL_SEGMENTER_EVENT::EARLY_COMMIT_WINDOW`. Four new host tests (`tools/segmenter_replay/test_segmenter_core.c`) cover fires-once-per-gap, latch-resets-on-onset, ordering-before-EOW, no-fire-below-min-silence; all 12 cases pass. Unblocks the decoder early-commit predicate (Vikunja #21).

### Changed

- **Rename `letter_classifier` → `letter_recognizer`** (Vikunja #41). The deepened module owns audio-to-letter-evidence end-to-end (per ADR-0005), not just classification. `git mv` preserved history on all 6 files. Public API renamed: `inference_init` → `letter_recognizer_init`, `inference_submit_utterance` → `letter_recognizer_submit_utterance`, plus `_reload_model` and the four `_get_*` stat getters. Internal signal-pipeline helpers (`load_model_from_partition`, `setup_interpreter`, `top_k_select`, `window_rms_dbfs`, the future `inference_run`) retained `inference_*` names per the PRD carve-out. Internal `inference_task` renamed to `recognizer_task`; logging TAG changed to `recognizer`.
- **Unified letter event vocabulary** (Vikunja #40, ADR-0006). Removed `SPELL_INFERENCE_EVENT::LETTER_TOP_K` and `SPELL_W_DETECTOR_EVENT::RETRACT_AND_REPLACE`. Added `SPELL_RECOGNIZER_EVENT::LETTER_RECOGNIZED` with payload `{ spell_letter_top_k_t top_k; uint8_t retract_count; }`. The decoder's letter-event handler will be one code path with no race against early commit. Emitter currently posts `retract_count = 0`; W-recovery (Vikunja #30) will be the only path that sets it to 2.
- `spell_letter_top_k_t` introduced as the per-utterance result type (`candidates[K]` plus `invoke_ms` for diagnostic). Replaces `spell_letter_topk_event_t`.

### Added

- ADR-0006 (`docs/adr/0006-unified-letter-recognized-event.md`) formalizes the unified letter event vocabulary.

### Removed

- `SPELL_INFERENCE_EVENT` event base + `SPELL_EVENT_LETTER_TOP_K` ID + `spell_letter_topk_event_t` payload.
- `SPELL_W_DETECTOR_EVENT` event base + `SPELL_EVENT_RETRACT_AND_REPLACE` ID + `spell_retract_and_replace_event_t` payload.
