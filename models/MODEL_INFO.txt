Input format
------------

The TFLite model expects MFCC features computed exactly as follows
(values from configs/config.yaml):

  Audio          : 16000 Hz, 16-bit, mono
  Pre-emphasis   : 0.97
  Window         : 320 samples (20 ms)
  Hop            : 160 samples (10 ms)
  FFT            : 512
  Mel filters    : 40, fmin=50 Hz, fmax=7600 Hz
  MFCC coeffs    : 20
  Channels       : 3 — static, delta, delta-delta
  Frame count    : 80 (audio padded/truncated to 800 ms)

Tensor layout (post-MFCC, pre-normalization):
  shape (80, 20, 3)  float32  = (frames, mfcc_coeffs, channels)

Normalization (mandatory — int8 quantization was calibrated against
the post-norm distribution):

  norm_mean.npy : float32, shape (1, 1, 20, 3)
  norm_std.npy  : float32, shape (1, 1, 20, 3)

  For each MFCC frame, apply elementwise:
      normalized = (mfcc_frame - mean) / std

  Then quantize to int8 using the model's input quantization params:
      int8_input = clip(round(normalized / scale + zero_point), -128, 127)

  Reference Python: model/production_model.py  (ProductionModel.predict —
                    owns post-norm + int8 quant + invoke + dequant)

Output format
-------------

  shape (1, 26)  int8 — dequantize with output scale/zero_point for
                       softmax probabilities.

  argmax → letter index, alphabetical order (0=A … 25=Z).

Confusion matrix (flat26_confusion_matrix.bin)
----------------------------------------------

For spell-word's noisy-channel word decoder. Built from the int8
model's predictions on the held-out test set (synthetic TTS), with
+1 Laplace smoothing applied before row-normalization so every cell
is strictly positive (log-domain decoding is safe).

  Format     : 26 × 26 float32, row-major, little-endian, no header
  File size  : 2,704 bytes (= 26 * 26 * 4)
  Semantics  : cell[i][j] = P(predicted=j | true=i), int8 model
  Source set : held-out test set (synthetic TTS, ~410 samples per row)
  Smoothing  : +1 (Laplace) before row-normalization

Limitation: the matrix reflects synthetic-TTS confusion structure,
not real-microphone confusions. If real-mic decoding accuracy
underperforms expectations, re-measuring the matrix on a labelled
real-audio corpus is the most likely lever — but that corpus does
not exist yet (out of scope as of 2026-05-02).
